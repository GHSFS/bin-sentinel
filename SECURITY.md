# Security Policy

## Supported Versions

Security updates are applied to the latest release series on the `main` branch.

| Version | Supported          |
| ------- | ------------------ |
| Latest (`0.x`) | :white_check_mark: |
| `< 0.1.0` | :x:                |

## Binary Parsing & Memory Safety Invariants

1. **Zero `unsafe` Code**: All PE32/PE32+ and Linux/BSD ELF64 binary structure parsers are implemented in 100% safe Rust using checked slice indexing and saturating/checked integer arithmetic.
2. **Untrusted Binary Bounds Protection**: Malformed `e_lfanew`, `e_phoff`, `e_shoff` offsets, truncated headers, overlapping section tables, and out-of-bounds raw data pointers are rejected deterministically without panicking or over-allocating memory.
3. **Constant-Time Patch Verification**: Declarative byte patches validate expected target bytes using branchless constant-time comparison (`constant_time_eq`) and compute pre-patch/post-patch SHA-256 digests prior to atomic file replacement.
4. **Sensitive Buffer Zeroization**: Intermediate binary patch buffers are scrubbed from memory on drop via `zeroize`.
5. **Bounded Linear Scanning & Deterministic Memory Consumption**: Cryptographic constant and S-Box scanning operates strictly over bounded byte slices with linear byte matching, preventing unbounded recursion or denial-of-service on large untrusted binaries.
6. **Bounded PE Import & Export Directory Parsing**: PE import descriptors (`IMAGE_IMPORT_DESCRIPTOR`), Import Lookup/Address Tables (ILT/IAT), and Export Directories (`IMAGE_EXPORT_DIRECTORY`) enforce hard caps (max 1,024 descriptors, max 4,096 thunks per descriptor, max 65,536 export symbols). RVA-to-file-offset translation guards against null RVAs, cyclic thunk tables, and truncated binary buffers, preventing infinite loops and out-of-bounds indexing.
7. **Pure-Rust Imphash & Dynamic API Hash Resolution**: RFC 1321 MD5 message digest calculation (`imphash`) and dynamic API hash evaluation (ROR13, CRC32, DJB2, FNV-1a) run in 100% safe Rust without external C dependencies, static bounds validation, and zero execution of untrusted binary code.
8. **Safe Static x86_64 Code Pattern Scanning & Evasive Syscall Telemetry**: Instruction pattern scanning operates in 100% safe Rust without code execution or dynamic disassembly runtimes. All slice reads are strictly bounds-checked with saturating offsets. Direct kernel system call stubs (SysWhispers/Hell's Gate), anti-debug timing probes (`RDTSC`/`RDTSCP`), and hypervisor queries (`CPUID`/`SMSW`) are statically extracted with section correlation and RWX anomaly flagging without executing untrusted payload bytes.
9. **Safe Declarative Pattern Rule Matching & Backtracking Defenses**: The hex and wildcard pattern rule scanner operates with strict resource bounds: maximum byte jump span of 4,096 bytes (`MAX_JUMP_LIMIT`), maximum match byte span of 65,536 bytes (`MAX_MATCH_SPAN`), recursion depth ceiling of 64 (`MAX_DFS_DEPTH`), and maximum match cap of 1,000 matches per pattern. Pure-Rust tokenization rejects unclosed jump brackets and uneven nibbles. Static pattern evaluation runs with zero execution of untrusted binary code and maps hits to PE/ELF section tables with automated RWX anomaly detection.
10. **Zero-Dependency Mach-O & Universal Fat Binary Safety Invariants**: All 64-bit Mach-O (`0xFEEDFACF`) and Universal Fat (`0xCAFEBABE`) binary parsers are implemented in 100% safe pure Rust with zero unsafe blocks. Multi-architecture slices, load commands (`LC_SEGMENT_64`, `LC_MAIN`, `LC_LOAD_DYLIB`, `LC_CODE_SIGNATURE`), and section tables enforce strict bounds checking (`checked_add`, safe LE/BE byte readers). Truncated slice offsets, malformed command sizes (`cmdsize < 8` or overflowing the Mach-O slice), and corrupted section bounds are deterministically rejected with descriptive errors. Digital code signature presence, PIE flags, stack execution permissions, and Writable/Executable (`RWX`) memory segments are audited statically without executing candidate binary code.
11. **PE Authenticode, Certificate Table & EOF Overlay Safety Invariants**: The Authenticode attribute certificate table parser and ASN.1 DER parser operate in 100% safe pure Rust with zero `unsafe` blocks. Parsing enforces strict resource ceilings (max 64 certificate entries, 4-byte ASN.1 length bounds, checked offset additions). Integer arithmetic for alignment (`(len + 7) & !7`) and section ranges uses checked and saturating operations, guarding against 32-bit and 64-bit wrap-around. Authenticode image hashing excludes PE `CheckSum` and Security Directory entries and processes sections in ascending file offset order without executing code. Appended EOF overlay detection computes physical image boundaries via checked section and certificate extents with bounded Shannon entropy profiling. Computed vs embedded digest comparisons employ branchless constant-time evaluation to eliminate timing side-channels.
12. **Binary Diff & Declarative Patch Recipe Manifest Safety Invariants**: The structural binary diff and declarative patch recipe manifest engine operates in 100% safe pure Rust with zero `unsafe` blocks. Multi-format parsing (PE, ELF, Mach-O) for section and RVA resolution strictly bounds offset traversal and suppresses panics on malformed or truncated binaries. Patch recipe manifests (`PatchRecipe`) enforce branchless constant-time comparisons (`constant_time_eq`) for target binary pre-patch (`source_sha256`) and post-patch (`target_sha256`) cryptographic verification, as well as per-operation expected byte checks. All patch offset calculations use checked arithmetic (`checked_add`) to prevent 32-bit and 64-bit integer overflows against file bounds. Tampered, overlapping, or out-of-bounds patch operations trigger atomic rollbacks with zero partial writes to disk, and all intermediate in-memory binary buffers are securely scrubbed on drop via `zeroize`.
13. **PE Rich Header Forensic Parsing & Authentic Checksum Safety Invariants**: The PE Rich Header parser and compiler toolchain fingerprinter operate in 100% safe pure Rust without unsafe code or third-party parsing runtimes. Rich marker identification is strictly confined to the DOS stub region bounded by `e_lfanew` (capped at 4,096 bytes) using checked byte slice indexing. The `DanS` entry marker and triple zero-padding verification enforce strict 4-byte and 8-byte alignment constraints, rejecting corrupted preamble structures before record decoding. Decoding loops enforce integer division checks (`records_bytes_len % 8 == 0`) and process records within pre-allocated bounds. The authentic Microsoft 32-bit `ROL` checksum computation executes over the DOS stub with `e_lfanew` zeroed out and accumulates `@comp.id` entries via wrapping 32-bit arithmetic (`wrapping_add`, `rotate_left`), eliminating integer overflow vulnerabilities. Decrypted record buffers are hashed with pure-Rust RFC 1321 MD5 and SHA-256 for threat intelligence pivoting without executing candidate binary code.
14. **Binary Deobfuscation Scanner & Key Recovery Safety Invariants**: The single-byte and multi-byte XOR, ADD, and ROL deobfuscation scanner operates in 100% safe pure Rust with zero `unsafe` blocks. Sliding-window brute-force analysis operates on bounded 256-byte windows with saturating stride offsets, preventing unbounded memory growth. Known-plaintext crib dragging (e.g. `http://`, `https://`, `MZ`, `\x7FELF`, `HKLM\`) validates key period consistency using checked arithmetic and bounds-checked slice indexing without memory leaks. Decoded candidate byte streams and scratch buffers are securely scrubbed from memory using `zeroize` upon completion. Payload classification (URLs, IPv4, Registry keys, PE/ELF/Mach-O magic) enforces strict format grammars, rejection of unprintable/control characters, and safe ASCII/UTF-8 decoding without executing untrusted payload bytes.
15. **PE Resource Directory (.rsrc), Application Manifest & UAC Privilege Safety Invariants**: The 3-level PE resource directory tree parser, application manifest extractor, and version info parser operate in 100% safe pure Rust with zero `unsafe` blocks. Multi-level directory traversal enforces strict cycle detection via visited offset tracking sets and recursion depth caps, preventing denial-of-service on cyclic or malicious resource tables. Resource string parsing (`IMAGE_RESOURCE_DIR_STRING_U`) and data entry offset translation enforce checked arithmetic (`checked_add`, `checked_mul`) and bounded slice lookups. Application manifest XML decoding safely handles UTF-8, UTF-16LE, and UTF-16BE encodings with BOM normalization and extracts User Account Control (`requestedExecutionLevel`, `uiAccess`, `autoElevate`) parameters using deterministic string matching without invoking external dynamic parsers or executing untrusted code. High-entropy resource payload flagging calculates Shannon entropy on bounded byte slices and flags potential packed or encrypted droppers.
16. **PE TLS Callback Directory & Exception Unwind (.pdata) Safety Invariants**: The PE TLS Directory (`IMAGE_DIRECTORY_ENTRY_TLS`) parser and x64 Exception Unwind (`IMAGE_DIRECTORY_ENTRY_EXCEPTION` / `.pdata`) parser operate in 100% safe pure Rust with zero `unsafe` blocks. Pointer translation between 32-bit/64-bit Virtual Addresses (VA) and Relative Virtual Addresses (RVA) uses saturating arithmetic and validates target offsets against mapped PE section boundaries. TLS callback array traversal enforces a hard ceiling of 256 callbacks (`MAX_TLS_CALLBACKS`) and terminates upon encountering null pointers or slice bounds, preventing denial-of-service or infinite loops on cyclic tables. The x64 `RUNTIME_FUNCTION` unwind table parser enforces a hard cap of 4,096 entries (`MAX_PARSED_FUNCTIONS`) and checks for inverted or zero function spans (`end_rva <= begin_rva`). `UNWIND_INFO` parsing validates header bounds, structure alignment, and code counts before extracting exception handler RVAs. Detected callbacks and exception handlers are cross-referenced with PE section permissions to identify non-executable targets or anomalous Read-Write-Execute (`RWX`) regions without executing candidate code.
17. **Base64, Hex & Encoded Payload Carving & Extraction Safety Invariants**: The encoded payload carving engine operates in 100% safe pure Rust with zero `unsafe` blocks. Base64 (Standard RFC 4648 and URL-Safe) and Hex sequence scanners enforce strict minimum length thresholds (default 16 bytes), hard caps on maximum carved payloads (`max_payloads`, default 500), and checked offset slicing to prevent memory exhaustion on large untrusted binaries. Candidate deduplication evaluates semantic confidence to eliminate false-positive collisions without unbounded allocation. Payload classification (nested PE, ELF, Mach-O, archives, scripts, and network IoCs) validates header magic numbers and structure bounds without executing decoded bytes. When payload extraction is requested (`--extract-dir`), the extraction path is verified using strict prefix checks (`dest.starts_with(out_dir)`) to eliminate path traversal vulnerabilities (`..` escape), and generated filenames follow a deterministic sanitized pattern (`payload_{id}_{offset}.{ext}`).
18. **Context Triggered Piecewise Hashing (CTPH / SSDEEP) & Fuzzy Similarity Invariants**: The piecewise fuzzy hashing and binary similarity comparison engine operates in 100% safe pure Rust with zero `unsafe` blocks. The rolling hash utilizes a bounded 7-byte sliding window with wrapping 32-bit arithmetic (`wrapping_add`, `wrapping_sub`), completely eliminating integer overflow vulnerabilities. Block hash accumulators use 32-bit FNV-1a with explicit zeroization on drop/completion (`Zeroize`) to prevent secret remnant exposure in memory. Dynamic programming matrices for Levenshtein distance and longest common substring (LCS) operate in $O(\min(M, N))$ auxiliary space with length bounding, preventing unbounded heap allocation. Section-level fuzzy hashing across PE, ELF, and Mach-O binaries strictly bounds raw offsets and sizes against physical file length, preventing out-of-bounds slice access on truncated or crafted executables.

## Reporting a Vulnerability

If you discover a potential security issue, parser crash on malformed inputs, or memory safety flaw:

1. **Do not open a public issue** with exploit details before a fix is available.
2. Report the finding via [GitHub Security Advisories](../../security/advisories/new) or contact the maintainers directly with a minimal reproduction case.
3. We review reports promptly and coordinate fixes and release notes upon resolution.
